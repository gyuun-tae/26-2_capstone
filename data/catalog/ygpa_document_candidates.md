## CSV 0.2 규격과 담당자 연결

기존 21열의 이름·순서를 유지하고 아래 4열을 끝에 추가했다. CSV는 UTF-8 BOM이며 날짜 문자열은 YYYY-MM-DD, 미확인은 빈 값이다.

| 추가 열 | 의미 |
|---|---|
| parent_source_url | 첨부 링크를 확인한 공식 부모 페이지. 기존 HTML 문서는 빈 값 |
| parent_published_at | 부모 게시글 작성일. 첨부 발행일·개정일과 구별 |
| format_hint | html / hwp / unknown. 파일 시그니처 확인 전 힌트 |
| discovery_id | 2026-09-27 탐색 보고서의 임시 번호. 기존 20건은 빈 값 |

신규 상태값은 date_status=unverified_attachment(첨부 날짜 미검증), access_status=attachment_link_verified(부모 페이지에서 첨부 링크 확인)다. review_status=attachment_and_rules_review를 사용한다. priority=extension_first_batch는 우선 7건, extension_next_batch는 후속 6건이다. sample_question은 원문 검토용 질문 제안이며 FAQ 최종평가 질문을 사용하지 않았다.

수집 정책 1.1은 기존 HTML 20개와 신규 첨부 13개의 source_url만 allowed_urls에 등록한다. allowed_parent_urls는 링크 근거를 재확인하는 부모 화면 전용이며 독립 학습 문서나 자동 순회 허용 목록이 아니다. attachment_sources는 doc_id·첨부 URL·부모 URL의 대응이다. 파일 다운로드 경로 전체나 file_no 전체를 허용하지 않는다. FAQ 차단·리다이렉트 금지·자동 링크 순회 금지를 유지한다.

현재 03_collect_remaining.py와 04_extract_remaining.py는 대상이 19건이어야 하고 HTML만 처리한다. 확장된 CSV로 바로 실행하지 않는다. 다음 3단계에서 신규 ID 선택, URL별 robots 검사, 첨부 응답 검증·저장, 재시도 및 provenance 검증을 적용해야 한다. 정책의 require_attachment_provenance는 그 요구사항이며 현재 코드가 이미 강제한다는 의미가 아니다.

문서 처리 담당자는 doc_id와 source_url을 유지하고 원본 해시·실제 파일 형식·수집 시각을 붙인다. 검색 담당자는 내용 검토 전의 첨부를 색인하지 않는다. 신규 수집 후 메타데이터에도 index_approved=false를 유지한다. FAQ는 최종평가 전용으로 제외한다.

3. **수집 담당:** 후보 CSV를 URL 목록으로 사용하고 실제 수집 시각·최종 URL·응답 상태·원본 경로·내용 해시를 별도 수집 기록으로 남긴다. 이 목록의 verified_on을 fetched_at으로 복사하지 않는다. 자동 수집 전 robots.txt와 이용 안내를 확인하고, 소량·간격 있는 요청으로 시작한다.
4. **문서 처리 담당:** doc_id를 그대로 이어받아 처리 문서와 청크에 원문 URL·문서 버전·근거 절을 연결한다. 날짜 미표시는 그대로 전달하고 표·그림·충돌 문서는 검토 후 사용한다.
5. **검색 담당:** 총괄표와 상세표의 같은 내용을 중복 증거로 계산하지 않는다. 검토 상태는 날짜 상태와 별개로 유지한다. 이 단계에서는 아직 승인된 색인 문서가 없다.
6. **API·화면 담당:** 출처 제목·URL·근거 절과 날짜 미확인 상태를 표시한다. 예약 제한 공지나 자료 충돌을 제거한 단정적 답변을 만들지 않는다.
7. **평가 담당:** sample_question은 질문 초안이다. 정답은 원문 재대조 후 작성하고, 날짜 불명확·그림 분기·예약 제한·표 충돌을 별도 검증 사례로 둔다.

## CSV 규격

UTF-8 BOM, 쉼표 구분, 첫 행은 영문 필드명이다. 날짜 문자열은 YYYY-MM-DD, 미확정 값은 빈 문자열이다. 쉼표가 있는 설명과 URL은 CSV 인용 규칙에 맞춰 저장했다.

| 필드 | 의미 |
|---|---|
| doc_id | 목록·원본·처리 문서·청크·평가를 연결할 문서 식별자 |
| title / source_url | 메뉴 맥락을 포함한 제목과 검증한 공식 URL |
| published_at / updated_at | 확인한 발행일·페이지 갱신일. 미확정은 빈 값 |
| date_status / date_evidence | not_displayed: 미표시, conflicting: 표기 충돌, page_updated: 페이지 갱신일 표시 및 그 근거 |
| question_category / sample_question | 질문 범주와 평가·설계에 사용할 질문 초안 |
| source_section | 확인한 본문 절 또는 표의 위치 |
| collection_method / chunking_notes | 수집 방식 제안과 문서별 분할 주의점 |
| access_status / access_note | web_readable: 공개 본문 열람 확인. HTTP 수집 성공을 뜻하지 않음 |
| verified_on / verification_method | 후보를 확인한 날짜와 방법. 실제 수집 시각과 구별 |
| review_status / review_notes | 검토 필요 사항과 구체적인 근거 |
| priority | first_batch: 첫 실습 후보 5건, supplementary: 추가 후보 |
| publisher / language | 제공 기관과 언어 |

검토 상태 코드: candidate_review = 수집 후보·내용 검토 전; image_review = 흐름도 대조 필요; date_recheck = 날짜 재확인 필요; static_fragment_only = 고정 문구만 수집; current_notice_and_conflict = 예약 제한·내용 충돌 검토; current_notice_review = 예약 제한 재확인; timetable_review = 시간표 별도 검토; content_conflict = 문서 간 내용 충돌; table_review = 표 추출 대조 필요; section_scope_review = 절 적용 범위 확인; current_rules_review = 현행 공고·규정 대조; attachment_and_rules_review = 첨부·현행 규정 대조.
