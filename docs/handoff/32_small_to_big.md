# 32 긴 법령 조문을 항 단위로도 색인 (small-to-big)

2026-10-13. 새 색인 `bge-m3-dense-c8f1fc61affe` (부모 1,269 + 법령 자식 519 = 1,788행, 승인 1,269 그대로). Neon 적재·검증 완료.
**Render는 아직 옛 색인** `bge-m3-dense-2e26c2fc2e81` — 바꾸려면 `INDEX_VERSION`만 교체.

## 왜

벡터 하나는 청크 전체의 평균이라 항이 여럿인 긴 조문은 한 항만 묻는 질문과 점수가 낮다.
h12 "감면 조항이 두 개 겹치면": 정답 문장이 LAW-010 제9조(1,507자) ⑤항 한 줄 → 벡터도 재정렬(512토큰)도 약했다 (31번).
법령 조문 1,010개 중 103개가 1,000자 초과.

## 구성

```text
색인:  부모 조문(그대로) + 자식 = 조문 제목 "제○조(…)" + 항 하나   (src/rag/parts.py, 16번 --parts)
검색:  자식이 걸리면 부모로 합침(가장 가까운 거리) → 문서·법령 상한 → 답변 모델엔 부모 조문 전체 (app/search.py)
재정렬: 자식이 걸린 근거는 부모 전체 대신 그 항(part)을 읽는다 (app/rerank.py)
```

- 대상: 법령(LAW-) 조문(`chunk_kind` article) 중 800자 초과 + 항 2개 이상 → 부모 88개(법령만 84) → 자식 519개
- 자식은 승인된 부모에서만 만들고 부모 승인을 따른다 (data/chunks에는 저장하지 않고 색인 빌드 때 만든다)
- 검색 SQL은 `parent_chunk_id`가 없는 옛 색인에서도 같은 결과 → 코드 배포와 색인 교체를 따로 할 수 있다
