# FAQ 75문항 측정 절차 (초안, 2026-11-03)

평가팀(채점)과 백엔드(답변 수집)가 같은 방식으로 재기 위한 절차. 근거 규칙은 [evaluation_boundary.md](../contracts/evaluation_boundary.md).

## 1. 원칙

1. FAQ 75문항은 **측정 전용**이다. 결과·사례·평가 보고서를 근거로 프롬프트·검색·자료·설정을 바꾸지 않는다 (경계 규칙 2·7번).
2. 개선은 개발 질문 묶음(`evaluation/datasets/`)과 실사용 로그로만 하고, 변경 기록에 그 근거를 남긴다.
3. 원인 실험(A~D 등)도 개발 묶음으로 한다. FAQ로 실험하면 그 세트는 개발에 쓴 것이 된다.

## 2. 측정 전: 버전 고정

측정할 버전마다 아래를 **먼저 기록**한다 (결과 파일 첫 줄 `meta`에 자동 기록되는 것 포함).

| 항목 | 예 |
|---|---|
| 버전 이름 | V3 |
| 코드 커밋 | `5205992` |
| 색인 | `INDEX_VERSION=bge-m3-dense-7747f421d88d` (승인 기록 날짜 포함) |
| 설정 | `RAG_RERANK`, `RAG_GATE`, `RAG_MAX_LAW`, `RAG_MAX_FORM` 등 |
| 모델 | 답변 Qwen3-32B-AWQ, 판정 Qwen3-14B-AWQ, 임베딩 BGE-M3 rev `5617a9f6`, 재정렬 bge-reranker-v2-m3 |
| 측정 시각·장소 | 날짜, 실행한 PC |

## 3. 답변 수집 (백엔드)

1. 스크립트 하나로 수집한다: `src/api/faq_answers.py` (질문만 입력, 정답은 읽지 않음, 대화 로그 안 남김).
2. **배포 서비스 `/chat`으로 보내지 않는다.** Neon 대화 로그에 FAQ 질문이 쌓이면 개발용 실사용 로그와 섞인다.
3. 시간 왜곡을 막는다.
   - 버전끼리 **동시에 돌리지 않고 차례로** 실행
   - 같은 GPU에서 다른 작업이 없는 시간에 실행
   - 시작 전 FAQ가 아닌 질문 1개로 예열(결과에 넣지 않음)
4. 결과: `evaluation/private/ygpa_faq/answers_<버전>_<날짜>.jsonl` + 엑셀 (Git 제외). 오류·빈 답이 있으면 그 문항만 다시 실행하고 기록에 남긴다.
5. 응답 시간은 **이 PC에서 조립 코드를 직접 부른 시간**이다 (Render 네트워크·콜드 스타트 제외). 발표에 쓸 때 이 조건을 함께 적는다.

## 4. 채점 (평가팀)

1. 정답·정답 근거는 **서비스 자료 기준으로 확정한 골든셋**을 쓴다 (작업본 `FAQ_golden_작업본_v0.xlsx`). 9/30 청크 178개 기준 정답은 쓰지 않는다.
2. 비교하는 버전은 **같은 문항 집합**으로 채점한다 (답한 문항 수가 다르면 공통 문항 값도 함께).
3. 지표: 검색 정밀도(정답 근거가 근거 5개 안), 인용 정확도, 환각률, 응답 시간(평균·중앙값·P95·첫 글자).
4. 채점자 2인, 1차 결과와 채점 기준이 다르면 그 차이를 적는다.

## 5. 보고

- 버전 기록(2번) + 수치 + 95% 구간 + 측정 조건(3-5)을 함께 낸다.
- 결과를 보고 수정했다면 그 뒤의 FAQ 수치는 "개발에 쓴 세트" 수치로 표시한다.
