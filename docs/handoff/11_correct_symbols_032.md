## 보정 근거

원본 PDF 9쪽을 220 DPI 전체 화면과 440 DPI 확대 영역으로 확인했다. 2017.02.21 부칙에서 규정명을 감싸는 기호는 『(U+300E), 』(U+300F)다. PDF /F7 글꼴의 ToUnicode는 서로 다른 문자 코드 0003과 0004를 모두 U+F000으로 연결한다. 해당 페이지 콘텐츠 스트림에서 /F7로 쓰인 두 코드를 확인했다. 보정 판단은 원문 시각 대조와 이 매핑 충돌에 근거한다. 글꼴의 Unicode cmap만으로 문자명을 복원한 것은 아니다.

- 원본 SHA-256: a35a81c74f818b537beb1c8b3e14358a2d8f09924bdcdc54cbc79430e3938595
- snapshot: 20260927T070447832791Z
- 기존 blocks.json 배열 인덱스: 8 (0부터), PDF 파일 페이지: 9 (1부터)
- 해당 문단 내 문자 오프셋: 688 → 『, 734 → 』 (Python 문자열 기준 0부터)
- 규정명: 무역항 등의 항만시설 사용 및 사용료 등에 관한 규정

이 원본 해시, 두 문자 수, 사이의 규정명, 페이지 위치가 모두 일치할 때만 보정한다. 다른 원본이나 다른 위치의 U+F000을 일괄 치환하지 않는다. 문자 앞뒤의 날짜·조건·본문은 바꾸지 않는다.

결과 경로는 `data/processed/YGPA-032/20260927T070447832791Z/text-corrected-v1/`다.

- document.txt: 기존 본문 중 두 문자만 보정한 전체 텍스트
- blocks.json: 해당 페이지 문단의 두 문자만 보정. 나머지 문단과 순서 보존
- document.json: 보정 본문·해시·문단 경로·correction_version·correction_manifest. document_version은 원본 해시를 유지
- corrections.json: 원본·입력·출력 해시, 보정 전후 문자, 본문 및 문단 오프셋, 글꼴 코드, 판단 근거, 남은 검토 항목

원래 processed 파일은 수정하지 않는다. 동일 결과는 유지하고 변조·다른 입력은 덮어쓰지 않는다. `index_approved=false`, `review_status=symbols_corrected_tables_and_currency_pending`다. 출력 폴더가 여러 개 생기므로 후속 코드가 모든 document.txt를 재귀적으로 모아 중복 색인하지 않도록 한다. 문서별 사용할 처리 버전을 명시해야 한다.
