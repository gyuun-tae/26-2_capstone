# 19. "확인 불가" 조기 판단 기준

검색 1위 점수가 기준보다 낮으면 API가 LLM을 부르지 않고 바로 `unknown`으로 답한다 (`src/api/app/rag_real.py`, 환경변수 `UNKNOWN_THRESHOLD`). 관련 질문과 무관한 질문의 1위 점수를 비교해 기준을 정한다.

```powershell
.\.venv\Scripts\python.exe -B .\scripts\19_unknown_threshold.py          # 가장 최근 색인, 로컬 CPU 모델
```

결과는 화면과 `data/index/<버전>/unknown_threshold.json`(Git 제외)에 남는다.

## 2026-10-02 결과 (색인 `bge-m3-dense-d67237d5942d`)

| 묶음 | 질문 수 | 1위 점수 최소 · 중앙 · 최대 |
|---|---:|---|
| 관련 (문서 목록 예상 질문) | 31 | 0.594 · 0.700 · 0.811 |
| 무관 (날씨·요리·인사 등) | 12 | 0.319 · 0.400 · 0.455 |
| 주변 주제 (항만·해운이지만 자료 없음) | 8 | 0.420 · 0.514 · 0.521 |

**기준 0.48**: 무관 질문은 모두 거르고, 관련 질문 최소값과는 0.11 차이를 둔다. 예상 질문은 문서 단어를 많이 써서 점수가 높게 나오므로, 실제 사용자 표현이 잘리지 않게 무관 쪽에 가깝게 잡았다. 주변 주제 중 6개는 기준을 넘는다 → LLM이 근거를 보고 `unknown`으로 판단해야 한다 (지시문 5번).

남은 일: 되묻기 판단이 안정적이지 않다 (위 "사용료" 질문). 실제 사용자 표현의 개발용 질문 묶음을 만들어 지시문·기준을 함께 다시 잰다. 첫 글자 시간(약 2~4초)의 대부분은 근거 5개를 읽는 시간이라, 근거 길이·개수 조정이 다음 후보다.

## 답변 형식 개선 (2026-10-02)

같은 6개 질문(민원·출입증 분실·입항 신고·실적증명서·체육시설 예약·출입증 연장)으로 전후 비교:

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| 근거 번호 | "[4]에 따르면"처럼 앞에 쓰거나 하위 목록에 빠짐 | 모든 문장·항목 끝, 번호 없는 줄 0개 |
| 구분선 `---` | 나옴 | 스트림에서 제거 (`RuleLineFilter`) + 지시문 금지 |
| Port-MIS 버튼 | 실적증명서·체육시설에도 붙음, 본문에 `[port_mis]` | 근거에 Port-MIS가 있을 때만 (코드 안전장치) |
| 응답 유형 | 답을 했는데 clarify(선택지 없음) | 선택지 없는 clarify는 answer로 처리 |

방법: 지시문에 항만과 무관한 형식 예시(도서관 회원증)와 되묻기 예시 추가, 질문 끝에 규칙 요약 한 줄. 처음에 항만 예시를 넣었더니 그 문장을 답에 그대로 베껴서 무관한 주제로 바꿨다. "사용료가 얼마예요?"는 여전히 되묻지 않고 unknown.
