# 현장 시범 운영 요건·비용 (초안, 2026-11-03)

중간발표(10/28) 15쪽 "11~12월 현장 실무자 사용 경험으로 MVP 보완"(멘토링 제안)을 하려면 필요한 것. 기존 [콜드 스타트 대책](render_cold_start_options_20261013.md)을 포함해 다시 정리했다.

## 0. 왜 필요한가 (실사용 로그, 11/3 집계)

- 개발자 외 질문 약 60건 중 **15건(25%)이 GPU가 꺼져 있어 답을 못 받음**
- **10/8 이후 8건 중 6건(75%) 실패.** 10/27(중간발표 전날) 오전 접속 5건도 전부 실패
- 10/8 이후 개선에 쓸 실사용 질문은 사실상 0건 → 시범 운영의 1순위 조건은 **정해진 시간에 서비스가 살아 있는 것**

## 1. 지금 구조에서 끊기는 곳

```
화면(Render 정적, 안 잠듦) → API(Render 무료, 15분 쉬면 잠듦) → Neon(무료) → 임시 터널(주소가 매번 바뀜) → 학교 GPU 서버(모델 4개, 손으로 켬)
```

| # | 끊기는 곳 | 증상 | 지금 대처 |
|---|---|---|---|
| ① | GPU 서버가 꺼짐 | "답변 서버를 사용할 수 없습니다" + 대표전화 | 사람이 tmux 6개를 켬 |
| ② | 터널 주소가 바뀜 | GPU를 켜도 Render가 옛 주소로 호출해 ①과 같은 증상 | Render `GPU_URL`을 손으로 고치고 재배포 |
| ③ | API 콜드 스타트 | 첫 질문이 약 1분 (10/13 측정 56초) | 없음 |

## 2. 요건별 선택지

### ① GPU 가동 시간 (팀장과 조율 필요)

- 모델 4개가 **GPU 2장을 다 씀**: GPU1 = 답변 Qwen3-32B(약 28GB), GPU0 = 임베딩·재정렬·판정(14B). 시범 운영 시간에는 다른 GPU 작업을 할 수 없음.
- 선택: (가) 평일 정해진 시간(예: 9~18시) (나) 시범 기간 내내 상시 (다) 정해진 날만
- 운영 시간 밖에는 지금처럼 안내 문구 + 대표전화가 나감 → 화면 첫 안내에 "운영 시간"을 적어 두면 실패로 보이지 않음 (FE 작업 작음)

### ② 고정 주소

| | 방법 | 비용 | 장점 | 주의 |
|---|---|---|---|---|
| A | 지금처럼 임시 터널 + 손으로 교체 | 0원 | 그대로 | 켤 때마다 Render 수정·재배포. 잊으면 ①과 같음 |
| B | 임시 터널 + **켤 때 Render 주소 자동 교체** (`start_tunnel.sh`가 Render API로 `GPU_URL` 갱신·재배포) | 0원 | 도메인 불필요, 코드만 추가 | GPU 서버에 Render API 키를 둬야 함(보안 팀원 확인). 재배포 1~2분 |
| C | **도메인 + Cloudflare 정식 터널** | 도메인 연 약 $10~15 | 주소 고정, SSE도 됨, 가동 보장 개선 | 도메인 결제·Cloudflare 계정 필요 |
| D | Tailscale Funnel (`*.ts.net` 고정 주소) | 0원 (무료 플랜) | 도메인 불필요 | GPU 서버에 tailscale 설치(학교 서버 정책 확인), 대역폭 한도 비공개 |
| E | ngrok 무료 dev 도메인 | 0원 | 계정당 주소 고정 | 무료 한도·경고 페이지 정책이 바뀌는 중 → 확인 필요 |

### ③ 콜드 스타트 (10/13 문서의 A/B/C 그대로)

- A 운영 시간대만 10분마다 깨우기(GitHub Actions, 0원) / B Render Starter(월 약 $7, 잠들지 않음) / C 시연 직전 손으로 깨우기

### ④ 그 밖에 시범 운영 전에 필요한 것

| 항목 | 내용 | 담당 후보 |
|---|---|---|
| 키 교체 | 평가 때 Render 등 접속 정보를 팀원에게 공유함 → GPU API 키·Neon 비밀번호·Render 계정 정리 | 백엔드 + 보안 |
| 로그 개인정보 | 외부인 질문이 쌓임 → 입력 금지 고지(화면에 있음), 보관 기간, 개인정보 가리기 | 보안 |
| 꺼짐 알림 | GPU·터널이 죽으면 알 방법 (관문 `/health` 주기 확인 → 알림) | 백엔드 |
| 대상·기간·배포 | 누구에게(YGPA 실무자 / 팀원·지인), 언제, 주소 전달 방법, 피드백 수집(👍👎 있음) | PM·팀장 |
| YGPA 창구 | 실무자 섭외·안내를 누가 할지 | 팀장 |
