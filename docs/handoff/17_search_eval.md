# 17. 개발용 검색 기준선

16번 색인으로 문서 목록 CSV의 **예상 질문(`sample_question`)**을 검색해, 그 질문의 정답 문서가 상위 k개에 나오는지 잰다. FAQ·최종평가 자료는 사용하지 않는다.

```powershell
.\.venv\Scripts\python.exe -B .\scripts\17_search_eval.py          # 가장 최근 색인
.\.venv\Scripts\python.exe -B .\scripts\17_search_eval.py --index data\index\<버전>
```

결과는 화면과 `data/index/<버전>/eval_catalog_questions.json`(Git 제외)에 남는다. 색인과 다른 모델 revision이면 멈춘다.

## 지표

- 문서 단위로 판정한다: 상위 k개 청크 중 정답 `doc_id`의 청크가 처음 나온 순위.
- `hit@1·3·5`: 정답 문서가 1·3·5위 안에 나온 질문 비율. `mrr@5`: 1/순위의 평균(5위 밖이면 0).
- 질문마다 정답 문서를 1개로 본다. 여러 문서가 정답일 수 있는 질문의 판정 단위는 평가 담당과 별도로 정한다.

## 해석과 한계

- 같은 주제의 이웃 문서(실적증명서 두 페이지, 출입·사용 신청서들, 부두 시설)끼리 순위가 바뀌었다. 3위 안에는 모두 들어오므로 생성기에 상위 5개를 넘기는 방식이면 근거는 확보된다.
- **낙관적인 수치다.** 예상 질문은 문서를 보고 작성해 문서의 단어를 많이 공유한다. 실제 사용자 표현(예: "배 들어올 때 신고")으로 쓴 개발용 질문을 따로 만들어 다시 재야 한다.
- 지명(여수항·광양항)이나 서식 이름처럼 정확한 단어가 중요한 질문은 키워드 검색(BM25) 결합으로 개선될 여지가 있다. 계획대로 이 dense 결과를 기준선으로 비교한다.
- 청크 단위 정확도(정답 문서 안에서 맞는 조항·표 행을 골랐는지)는 아직 재지 않았다.
