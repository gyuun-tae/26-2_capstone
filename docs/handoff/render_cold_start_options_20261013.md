# Render API 잠들기(콜드 스타트) 대책 — 팀장 검토용 (2026-10-13)

## 문제

API(`https://ygpa-api.onrender.com`)는 Render **무료 web service**다. 15분 동안 요청이 없으면 잠들고, 다음 요청에서 깨어나는 데 약 1분 걸린다.
10/13 배포 직후 첫 질문의 첫 글자가 **56초** 뒤에 나왔다(평소 2~3초). 시연·심사 때 첫 질문이 이러면 고장으로 보인다.
화면(정적 사이트 `two6-2-capstone-web.onrender.com`)은 잠들지 않는다 — API만 해당.

Render 무료 조건 ([Render Free 문서](https://render.com/docs/free)):
- 15분 무요청 → 잠듦, 깨어나는 데 약 1분
- 워크스페이스당 무료 인스턴스 시간 **월 750시간**. 잠든 동안은 쓰지 않음. 넘으면 **그 달 남은 기간 무료 web service 전부 정지**
- 정적 사이트는 인스턴스 시간에 세지 않음 (대역폭·빌드 시간만)
- 외부로 나가는 트래픽이 지나치게 많으면 무료 서비스를 정지할 수 있다고 함 (우리 API는 GPU 터널·Neon 호출이 있으나 질문 수가 적음)

## 선택지

| | 방법 | 비용 | 장점 | 주의 |
|---|---|---|---|---|
| A | **시연·사용 시간대에만 외부에서 깨우기** (10분마다 `/health` 요청) | 0원 | 무료 유지. `/health`는 서버 안만 확인(Neon·GPU 호출 없음) | 24시간 깨우면 한 달 약 720시간 → 750시간 한도에 거의 닿음. 같은 워크스페이스에 다른 무료 web service가 있으면 넘칠 수 있음 → **운영 시간대(예: 9~23시)만** 깨우면 월 약 430시간 |
| B | **Starter 인스턴스로 전환** | 월 약 $7 (512MB, 0.5 CPU — 무료는 0.1 CPU) | 잠들지 않음. CPU 5배라 검색 결과 정리·스트리밍도 여유 | 결제 수단 필요. 가격은 제3자 정리 기준이라 [Render 가격 페이지](https://render.com/pricing)에서 확인 필요 |
| C | **시연 직전에 손으로 한 번 질문** | 0원 | 준비 없이 바로 가능 | 잊으면 그대로 1분. 15분 넘게 비면 다시 잠듦 |

A의 깨우는 주체 후보: GitHub Actions 예약 실행(저장소에 워크플로 파일 하나, 5분 단위까지 가능하나 몇 분 늦을 수 있음) 또는 외부 모니터링 서비스(UptimeRobot·cron-job.org 등, 가입 필요).

## 백엔드 추천

1. **지금~시연 전: A (운영 시간대만)** — 비용 없이 바로 효과. 팀원 시험 사용 기간에도 도움
2. **최종 시연·심사 주간: B 검토** — 그 기간만 Starter로 올렸다 내리는 것도 가능 (Render는 인스턴스 종류를 바꿔도 주소 유지)
3. GPU 서버 쪽 문제(임시 터널 주소가 재시작마다 바뀜, GPU를 꺼 두면 "답변 서버를 사용할 수 없습니다" 안내)는 별개 — 고정 주소(도메인 + 정식 터널)는 따로 검토

## A를 고르면 (GitHub Actions 예시 — 아직 저장소에 넣지 않음)

`.github/workflows/keep-api-warm.yml`:

```yaml
name: keep-api-warm
on:
  schedule:
    - cron: "*/10 0-14 * * *"   # UTC 0~14시 = 한국 9~23시, 10분마다
  workflow_dispatch:
jobs:
  ping:
    runs-on: ubuntu-latest
    steps:
      - run: curl -fsS --max-time 90 https://ygpa-api.onrender.com/health
```

넣으면 main에 올리는 순간부터 동작하므로, 팀장 확인 뒤 넣는다. 끄기는 파일 삭제 또는 GitHub Actions 화면에서 비활성화.
