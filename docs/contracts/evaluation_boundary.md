# FAQ 평가 데이터 분리 규칙

결정일: 2026-09-23. 사용자 지시에 따라 전체 진행 계획 초안보다 이 규칙을 우선 적용한다.

## 평가 전용 출처

- 여수광양항만공사 [자주 묻는 질문 게시판](https://www.ygpa.or.kr/hmpg/ygpa/comu/faqs/bordContListPage.do?bbs_no=230)
- 해당 게시판의 질문·답변, 상세 페이지, 첨부, 복사본, 번역·요약·바꿔 쓰기 파생물은 최종평가 전용이다.
- FAQ 본문은 이번 개발 단계에서 열람하거나 다운로드하지 않았다. 현재 후보 20건에는 FAQ 경로 및 bbs_no=230 URL이 없다. 기존 모델의 사전학습 자료에 공개 FAQ가 포함됐는지는 확인할 수 없다.

## 분리 범위

1. FAQ를 파인튜닝·학습 데이터, 임베딩 대상, 검색 저장소, 질의 확장·재정렬 학습, 시스템 프롬프트 예시, 개발용 테스트 정답으로 사용하지 않는다.
2. FAQ의 질문을 보고 문서 선택·프롬프트·검색 설정·청크 크기를 조정하지 않는다. 현재 후보 목록의 질문 예시는 FAQ를 보지 않고 작성한 개발용 초안이며 최종 FAQ 정답이 아니다.
3. 데이터 수집은 명시한 URL만 허용한다. 링크 순회와 자동 리다이렉트는 끈다. /hmpg/ygpa/comu/faqs/ 경로 또는 bbs_no=230이면 허용 목록보다 우선 차단한다.
4. 다른 업무 안내 문서에 독립적으로 기재된 같은 업무 사실은 RAG 근거로 사용할 수 있다. FAQ Q&A 원문이나 그 복사본을 우회 반입하는 것은 금지한다. 질문 문구가 같은 변형을 개발·최종평가에 나누어 넣지 않는다.
5. 평가 담당자는 개발 설정을 확정한 뒤 별도 환경에서 FAQ 평가 세트를 보관한다. 이 프로젝트에서 임시 보관이 필요하면 evaluation/private/ygpa_faq/를 사용하고 개발 도구·색인 입력에서 제외한다. .gitignore는 Git 공유 제외 기능이며 접근통제나 색인 차단 기능이 아니다.
6. 최종평가 시 모델에는 질문만 보낸다. 정답은 응답 생성이 끝난 뒤 별도 채점기에 전달한다. 채점 모델에 정답을 제공하는 경우에도 응답 생성 모델의 대화·색인과 분리한다.
7. 최종 FAQ 평가 결과를 보고 수정하면 해당 세트는 이후 개발에 사용된 세트로 취급한다. 최종 성능을 주장하려면 수정에 쓰지 않은 별도 평가 자료로 다시 평가하고 버전을 기록한다.

## 담당별 인수인계

| 담당 | 적용할 규칙 |
|---|---|
| 수집 | [기계 판독 정책](data_separation_policy.json)의 URL 허용·차단 기준을 요청 전에 검사. 리다이렉트·링크 자동 순회 금지. 첨부는 정책에 개별 등록한 URL과 부모 출처를 확인한 경우만 수집 |
| 문서 처리 | FAQ 원문·복사본·파생물을 받지 않음. 메뉴·푸터를 제거하고 문서 ID·출처 URL 유지 |
| 검색 | 프로젝트 전체를 재귀적으로 읽지 않음. 승인된 청크 명세만 색인하고 원문 URL 차단을 다시 적용 |
| API·프롬프트 | FAQ 정답을 응답 생성 입력·예시·캐시에 넣지 않음 |
| 평가 | 질문·정답·원문 버전·확인 시점을 별도로 고정. FAQ가 낡거나 현재 안내와 충돌하면 평가 문항을 검토 대상으로 표시 |
| 배포 | 평가 원본과 정답을 앱 이미지·서버 배포·공개 저장소에 포함하지 않음 |

## 첫 수집 단계 기록 — 2026-09-23 (과거 범위)

현재 정책의 허용 URL은 YGPA-001 민원신청안내 1건이다. 20건 후보 목록은 그대로 보관하지만 이번 실습에서 전부 수집하지 않는다. robots.txt 확인은 수집 규칙 확인용 메타데이터 요청으로만 사용하며 검색 자료로 저장하지 않는다.

사용자에게 제공하는 수집 코드는 공개 안내 HTML과 수집 메타데이터만 저장하고 index_approved=false로 표시한다. 원문 저장은 색인 승인과 별개다. 실제 원본 수집은 사용자가 코드를 복사해 실행한 뒤 확인한다.

URL 규칙만으로 다른 URL에 복제된 FAQ 문구까지 자동 판별할 수는 없다. 문서 검토에서 복사본이 발견되면 해당 문서도 색인에서 제외한다. 이후 수집 범위를 넓힐 때 정책과 검토 기록을 함께 갱신한다.



## 현재 확장 범위 — 2026-09-27

현재 목록은 HTML 20건과 첨부 후보 13건, 총 33건이다. FAQ 차단 범위와 최종평가 전용 원칙은 그대로 유지한다. 첨부는 `attachment_sources`에 ID·파일 URL·공식 부모 URL을 개별 등록하고, 부모 화면에서 직접 연결을 확인한 경우에만 수집한다. 다운로드 경로 전체를 허용하거나 FAQ 첨부를 허용한 것은 아니다.

첨부 수집 코드는 제공됐으며 이 단계에서는 오프라인 검증만 했다. 실제 다운로드는 실행 안내에 따라 사용자가 수행한다. 부모 HTML은 출처 증명용으로만 보관하고 검색에 넣지 않는다. URL 차단으로 다른 문서 내부의 FAQ 복사본까지 판정할 수 없으므로 내용 검토에서도 제외 규칙을 적용한다.
